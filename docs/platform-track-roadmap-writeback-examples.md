# 平台专项路线图回写示例

更新时间：2026-04-21

这份文档不讲完整模板，而是直接给出“平台专项收口后，路线图里该怎么回写”的短样例。

它适合解决这几个问题：

- 平台专项已经有收口结论，但路线图里还总是回写成长段说明
- 已经有平台专项摘要模板了，但缺少更接近真实路线图语气的短样例
- 想把 mac / iOS / 小程序 这类平台节点稳定控制在“可快速浏览”的摘要级别

建议配合：

- [平台专项收口摘要模板](./platform-track-closure-summary-template.md)
- [平台首发摘要模板](./platform-first-release-summary-template.md)
- [发布节点回写示例](./release-roadmap-writeback-examples.md)

## 1. 使用方式

推荐顺序：

1. 先在平台专项文档或收口摘要里保留完整边界、风险和下一步动作。
2. 再从完整内容里抽 2 到 4 行，回写到路线图。
3. 路线图里只保留“阶段、范围、边界、下一步”，不要再塞实现过程。

路线图里的目标是让人一眼看出：

- 这是哪个平台节点
- 当前处在什么阶段
- 已明确纳入了什么
- 明确延后了什么
- 下一步往哪推

## 2. mac 回写示例

### 2.1 首发准备完成

~~~text
- R-mac-first 进入首发准备完成：
  - 首发范围已收口到构建、更新、数据目录、权限与回滚路径
  - 暂不扩展通用自动化打磨和更大范围的桌面特性补齐
  - 下一步进入签名、公证和首发验收
~~~

### 2.2 首发后继续补边界

~~~text
- R-mac-first 首发后继续补边界：
  - 首个可安装版本已具备对外可用能力
  - 当前继续压实签名、公证、更新安装链路和异常回退
  - 后续仍以稳定首发体验优先，不立即扩范围
~~~

## 3. iOS 回写示例

### 3.1 Safe Track 边界确认完成

~~~text
- R-ios-safe-track 边界确认完成：
  - 首发只保留登录、项目列表、消息查看、轻量回复、文件接收
  - 不按安卓镜像版推进，不承接完整远控和重后台保活
  - 下一步先复用现有协议与同步链路，补首发验收
~~~

### 3.2 首发前待验证

~~~text
- R-ios-safe-track 进入首发前验证：
  - Safe Track 范围与延后范围已明确
  - 当前重点转向协议复用、弱网恢复和审核约束核查
  - 通过首发验收后再决定是否扩大能力边界
~~~

## 4. 小程序回写示例

### 4.1 Lite 边界确认完成

~~~text
- R-mini-lite Lite 边界确认完成：
  - 首发坚持轻入口定位，只承接查看、快速回复、状态确认和文件接收
  - 不承担完整实时控制终端角色，也不做重设置页和大缓存
  - 下一步补轻量验收和交互细节，不扩成完整移动端
~~~

### 4.2 首发后继续压实轻入口

~~~text
- R-mini-lite 首发后继续压实轻入口：
  - 当前版本已验证轻量查看与快速回传可用
  - 后续继续优化弱网刷新、重连反馈和边界提示
  - 仍保持 Lite 定位，不回到全量能力诉求
~~~

## 5. 不推荐写法

不要在路线图里继续写这种又长又混的段落：

~~~text
本轮平台专项整体推进比较顺利，已经把不少问题都收掉了，后面还会继续根据情况补齐体验、
协议和发版细节，等验证完成以后再看是否扩大范围。
~~~

原因：

- 看不出当前究竟到了哪个阶段
- 看不出已经纳入和明确延后的范围
- 看不出下一步是验收、首发还是继续补边界
- 很容易把路线图重新写回大而散的过程文档

## 6. 当前结论

后续平台专项节点回写时，优先复用这份文档里的短样例，把平台专项收口摘要再压成路线图语气，避免总览文档再次膨胀。
