# 平台专项验收未通过后的短回写示例

更新时间：2026-04-22

这份文档不再讲完整模板，而是直接给出“平台专项在验收阶段没过，需要退回补问题、延后首发或重新收口时，路线图里该怎么回写”的短样例。
它适合解决这几个问题：

- 平台专项很多时候不是实现完就直接往前推，而是会在验收阶段被打回，但路线图里缺少明确的“验收未通过”语气
- 已经有阶段切换、首发延期和风险样例，但缺少专门描述“验收没过，先回补再说”的写法
- 想把 mac / iOS / 小程序 这类平台节点验收失败的原因、当前保留范围和回补动作稳定控制在摘要级别

## 1. 使用方式

推荐顺序：
1. 先在平台专项文档、验收清单或问题清单里写清楚哪些检查没过、当前保留哪些范围、回补后再看什么。
2. 再从完整内容里抽 2 到 4 行回写到路线图。
3. 路线图里只保留“哪类验收没过、当前先回退到什么边界、先补什么、补完后再进入哪一步”，不要把验收现场过程整段搬进去。

路线图里最好让人一眼看出：

- 这是验收未通过，不是单纯延期或暂停
- 当前退回到哪个边界继续收口
- 验收没过的核心问题是什么
- 下一步是重新验收、延后首发还是收窄边界

## 2. 因主链路验收未通过退回

### 2.1 mac

~~~text
- R-mac-first 当前验收未通过：
  - 安装、更新或回退链路验收仍有阻塞问题，当前先退回补主链路
  - 首发边界继续保留在构建、签名、安装和更新，不并回更大桌面范围
  - 下一步先修主链路问题并重跑验收，再决定是否恢复首发准备
~~~

### 2.2 iOS Safe Track

~~~text
- R-ios-safe-track 当前验收未通过：
  - 登录、消息查看或文件接收链路还有阻塞点，当前先不推进首发
  - Safe Track 边界继续维持，不扩到完整远控能力
  - 下一步先补主链路问题并复测，再决定是否恢复首发待验证阶段
~~~

## 3. 因弱网或恢复链路验收未通过

### 3.1 iOS Safe Track

~~~text
- R-ios-safe-track 当前验收未通过：
  - 弱网恢复和后台受限场景验收还没过，当前先退回补恢复链路
  - 当前只保留已稳定的轻量主链路，不把更深端侧交互继续带进验收范围
  - 下一步先补恢复与审核相关问题，再重新进入验收
~~~

### 3.2 小程序 Lite

~~~text
- R-mini-lite 当前验收未通过：
  - 轻入口状态刷新和快回反馈在弱网场景下还不够稳，当前先退回补轻量体验
  - Lite 定位继续有效，不因为验收失败而直接扩大产品范围
  - 下一步先修轻量链路问题并复测，再判断是否恢复首发准备
~~~

## 4. 因边界或交互核查未通过

### 4.1 mac

~~~text
- R-mac-first 当前验收未通过：
  - 首发前交互和安装流程核查没过，当前先收回到最小可发布主链路
  - 不把桌面体验增强继续塞进这轮验收范围
  - 下一步先补核查问题并重跑首发验收，再决定是否恢复原计划
~~~

### 4.2 小程序 Lite

~~~text
- R-mini-lite 当前验收未通过：
  - Lite 交互细节和轻量验收标准还没对齐，当前先退回补最小主链路
  - 当前只保留查看、快回和状态确认边界，不追加更重交互
  - 下一步先补轻量交互核查，再决定是否继续首发节奏
~~~

## 5. 验收未通过但专项继续推进

### 5.1 iOS Safe Track

~~~text
- R-ios-safe-track 当前验收未通过但继续推进：
  - 验收失败后当前不转暂停，继续只围绕 Safe Track 主链路补问题
  - 当前不把延后范围自动并回，也不扩大产品边界
  - 下一步先修验收阻塞项并复测，再决定是否继续首发准备
~~~

### 5.2 mac

~~~text
- R-mac-first 当前验收未通过但继续推进：
  - 虽然没过，但专项不退出，继续围绕安装、更新和回退链路做收口
  - 更大范围桌面体验和自动化能力继续延后，不进这轮复测
  - 下一步先完成复测和首发前检查，再决定是否恢复发版计划
~~~

## 6. 不推荐写法

不要在路线图里继续写这种又长又模糊的段落：

~~~text
这个平台最近在验收的时候还有一些问题，所以后面可能还得再改一改，具体算不算没过、现在先回退到哪里、后面什么时候再验收，通过后要不要继续发，之后再看情况决定。
~~~

原因：

- 看不出是不是已经明确判定验收没过
- 看不出现在退回到了什么边界
- 看不出先补什么问题
- 看不出补完后是重新验收还是直接延期

## 7. 当前结论

后续平台专项如果不是正常通过验收，而是在验收阶段被打回，优先复用这份文档里的短样例，把失败原因、当前保留边界和回补动作压成路线图语气，避免总览继续膨胀。
