# 微信小程序 Lite 边界说明

更新时间：2026-04-19

这份文档用于定义 `R-mini-lite` 的边界。小程序的目标不是复刻 Android，而是做一个“快进来、快查看、快回复、快离开”的轻量入口。

## 1. 目标

小程序 Lite 首发优先解决：

- 快速查看消息和状态
- 快速回复
- 快速接收文件
- 快速做轻操作

不追求：

- 长时间前台实时控制
- 复杂设置
- 重型任务编排

## 2. 产品定位

定位：轻量副客户端。

适合场景：

- 外出时临时查看项目状态
- 看最新消息和活动
- 快速回一句话
- 接收别人发来的图片或文件
- 点一下“刷新”“重连”“重新拉取”这类轻操作

不适合场景：

- 长时间盯多会话实时输出
- 当作主控制台使用
- 承担复杂后台恢复和任务管理

## 3. 首发能力边界

### 3.1 必做

- 登录与账号识别
- 项目消息列表
- 项目聊天只读 + 快速回复
- 协作组消息查看
- 最近任务状态查看
- 文件消息接收与下载
- 一键刷新 / 一键重连类轻操作入口

### 3.2 可选但不阻塞首发

- 最近访问项目
- 轻量未读数
- 图片快速预览
- 常用回复模板

### 3.3 不进首发

- 复杂设置页
- 本地大型缓存
- 重型任务配置编辑
- 长时间实时控制终端能力

## 4. 缓存边界

小程序的缓存必须更轻，优先只保留：

- 最近访问项目列表
- 最近消息窗口
- 基础登录态
- 轻量未读和时间戳信息

不建议首发保留：

- 完整消息大历史
- 大型附件长期缓存
- 多层会话快照数据库

## 5. 消息与同步边界

小程序仍然应复用现有主链路，而不是另起协议。

继续遵守：

- 缓存优先
- 增量同步
- 按需补拉
- 项目级授权裁切

不建议首发做：

- 大量后台长连接恢复策略
- 高频全量目录刷新
- 多会话实时流式输出主控视图

## 6. 文件边界

小程序首发只做“消息中的文件接收端”。

要求：

- 消息里可见图片和文件
- 可下载
- 可做轻量预览时就预览
- 不单独做复杂传输中心

发送文件能力建议等统一文件传输底座稳定后再评估。

## 7. 登录态与安全边界

首发必须保持：

- 与当前账号体系一致
- 项目级授权继续生效
- 不绕过 `effective-scope`
- 不把全项目目录默认暴露给轻客户端

## 8. 首发验收清单

至少验证：

- 登录
- 项目列表展示
- 聊天只读与快速回复
- 协作组消息查看
- 最近状态查看
- 图片 / 文件接收与下载
- 项目级授权限制
- 刷新 / 重连类轻操作

对应路线图节点：

- `R-mini-lite`

## 10. 当前结论

小程序 Lite 的价值不在“功能全”，而在“进入快、查看快、回复快、离开快”。首发必须坚持轻客户端定位，不能把它做成 Android 的缩略复制品。
